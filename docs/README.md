# 문서 (docs/)

투윤백 안전 알림 시스템 고도화 프로젝트의 관리 문서입니다. 전체 목록과 링크는 **[00_산출물목록.xlsx](00_산출물목록.xlsx)**에서 볼 수 있습니다.

## 폴더 구성
```
docs/
├── 00_산출물목록.xlsx      # 전체 산출물 목록 (위치 링크, 작성 상태, 내용 요약)
├── 1_착수/                 # 01 프로젝트헌장, 02 이해관계자등록부, 03 팀구성·역할배정
├── 2_계획/                 # 04~24 계획서·기준선 (범위, 일정, 원가, 자원, 위기, 품질, 조달, 의사소통)
├── 3_실행/                 # 25 작업성과, 26 이슈, 28 지식관리, 29 품질보증, 30 정보배포, 31 공급자선정
├── 4_감시통제/             # 27 변경요청서, 32 프로젝트성과보고서
├── 5_종료/                 # 33 (단계) 종료보고서, 34 교훈정리보고서
├── 요구사항/               # 요구사항정의서.xlsx + 원본 데이터 requirements.json
└── _source/                # 문서 생성 스크립트와 원본 데이터 (직접 편집하는 곳)
```
여러 프로세스가 같은 파일을 쓰는 경우(예: 21 위기등록부, 27 변경요청서)는 처음 나오는 그룹 폴더에 한 번만 둡니다.

## 읽는 법
- **노란 배경** = 저장소에서 확인할 수 없는 가정값·계획(안)입니다 (일정, 단가, 성능 목표 등). 계획 기준선 승인(활동 A06) 때 확정합니다.
- **파란 글자** = 입력값, **검은 글자** = 수식입니다. 엑셀의 입력값을 바꾸면 합계·일정·EVM이 자동으로 다시 계산됩니다.
- **[확인 필요]** = 원 개발팀원 연락처처럼 아직 모르는 정보입니다.
- 사실 데이터(요구사항, 이슈, 변경 요청, 배포 이력)는 저장소 기록(ai/tasks, KNOWN_ISSUES, git log)에서 가져왔습니다.

## 다시 만들기
문서 내용은 `_source/plan.py`(일정·자원·위기·이슈 등)와 `요구사항/requirements.json`(요구사항·작업)에서 생성됩니다. 문서를 직접 고치지 말고 원본을 고친 뒤 다시 생성하세요.
```bash
python docs/_source/build_all.py                                                   # PM 산출물 34종 + 목록
python ai/tools/build_requirements.py docs/요구사항/requirements.json docs/요구사항/요구사항정의서.xlsx --sync-tasks
```
다시 생성하면 엑셀에 직접 입력한 내용은 덮어쓰입니다. 실행 기록용 대장(26, 28, 29, 30 등)을 직접 채우기 시작했다면 그 파일은 생성 대상에서 빼고 관리하세요.
