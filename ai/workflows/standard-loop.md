# 표준 작업 루프

모든 작업(기능 추가, 버그 수정, 분석)은 이 5단계를 따릅니다. 오케스트레이터(메인 Claude)가 진행하고, 각 단계는 표에 적힌 에이전트가 맡습니다.

| 단계 | 담당 | 산출물 | 완료 조건 |
|---|---|---|---|
| 1. 기록 | 오케스트레이터 | `ai/tasks/NNNN-*.md` (`python ai/harness.py new-task "제목"`) | 목표·범위·완료 조건이 적혀 있음 |
| 2. 분석·계획 | 오케스트레이터 (+ 필요하면 `data-analyst`) | task 파일의 "계획" 섹션 | 수정할 파일과 API 계약 영향이 명시됨 |
| 3. 구현 | `backend` / `frontend` / `data-analyst` | 코드 변경 | 담당 범위 밖 파일은 건드리지 않음 |
| 4. 검증 | 오케스트레이터 | `python ai/harness.py check` 결과 | error 0개 (warn은 task에 기록) |
| 5. 리뷰·커밋 | `reviewer` → 오케스트레이터 | 리뷰 결과, 커밋 | 리뷰 지적을 반영했거나 보류 사유를 기록함 |

## 분배 규칙
- 프론트와 백엔드에 걸친 변경(API 계약 변경)은 **backend 먼저**, 그다음 frontend 순서로 진행합니다. 계약은 `ai/context/PROJECT.md` §4에 반영합니다.
- 서로 겹치지 않는 범위의 작업(예: 노트북 분석과 UI 수정)은 병렬로 진행합니다.
- 실행에 모델 가중치가 필요한 검증은 로컬에서 할 수 없습니다. "실행 안 함"을 task에 분명히 적습니다.

## 금지
- 모델 가중치, 원본 데이터, `node_modules`, 비밀값 커밋 → `forbidden-files`, `secrets` 검사가 막습니다.
- `harness check`에서 error가 남은 상태로 커밋
- 검증하지 않은 것을 "확인했다"고 보고
